Gawaah v1: An Archive Assistant for Urdu Newsrooms

SyncNebula Azure OpenAI • Azure AI Search • Azure Functions

The Question Nobody Has Time to Answer

Every newsroom has the same quiet problem. A guest says something on air, and someone in the control room wonders: didn't we report the opposite last year? The answer is somewhere in the archive, but finding it takes minutes nobody has, especially when the archive is a mix of Urdu and English and people search in Roman Urdu on their phones.

Gawaah is an attempt to fix that. A producer types a question in Urdu, Roman Urdu or English, and gets a short answer built only from the newsroom's own published coverage, with links to the original articles. This post covers version 1: a working prototype. More updates will follow as it grows.

1. What Gawaah v1 Does

  • Answers with sources. Every answer links to the original articles and shows their dates.
  • Works across languages. An English question can find an Urdu article, and an Urdu question can find an English one.
  • Forgives messy input. Roman Urdu spellings and misspelled names still find the right story.
  • Understands time. Ask what a minister said "in June 2024" and it searches that month.
  • Says "not found" instead of guessing. If the archive has no coverage, it says so, and it will not stitch unrelated stories into an answer.
  • Shows how coverage changed. If a statement in June was followed by a different decision in September, it reports both, with dates. It never calls anyone a liar. It reports what was published and when, and the producer decides what to do with it.
  • Writes an on-air line. Next to the answer, it drafts a one-line summary that fits an anchor's screen, and the producer can edit it.
  • Sends evidence to the anchor. One click puts the line and its sources on a separate anchor screen within about two seconds.

2. How It Works

The pieces are few, and each has one job:

  • Azure OpenAI (GPT-5.5) — understands questions and writes the grounded answers.
  • An embedding model — turns text into numeric "meaning fingerprints", so searches match on meaning as well as exact words.
  • Azure AI Search — stores the archive and finds the best matching passages using keyword and meaning search together.
  • Azure Storage — keeps the original articles, and a small table that carries evidence from the producer to the anchor.
  • Azure Functions — the API that ties it together.
  • Two simple web pages — one for the producer, one for the anchor.
Question → rewritten into English and Urdu search queries → search the archive → write an answer from the best passages only → show it with sources → optionally send the one-line version to the anchor's screen.

3. The Step That Made the Biggest Difference

The first version simply searched with the question as typed. It worked for most questions, but failed in a clear pattern: an English question about a story published in Urdu kept returning English articles instead, because words and meaning matched better within the same language.

The fix was a short rewrite step before searching. A model turns each question into a clean English query and a clean Urdu query, normalises name spellings, and pulls out any date range mentioned. The search then uses both. Misspelled names, Roman Urdu and cross-language questions all improved at once, and date questions started using a real date filter instead of hoping the model would guess.

4. Teaching It to Say "Not Found"

Search always returns something, even when the archive has nothing useful. A tool that answers anyway is dangerous in a newsroom, where one invented answer on air costs far more than ten honest "not found" replies.

So the answer step has strict rules: use only the passages provided, answer only the part that is actually supported, state what is missing, and refuse when the passages merely share a name or place with the question without answering it. The hardest tests were the near-misses, such as a real person's name paired with a topic they never spoke about.

Lesson: retrieval finds candidates; it is the answer step's job to decide whether any of them actually answer the question.

5. How It Was Tested

The test archive was small and synthetic: 10 invented English and Urdu articles, with 25 test questions. Twenty had answers in the archive and five did not. The questions covered English, Urdu, Roman Urdu, misspelled names, date-based questions and a deliberately tricky case where two articles from different months seem to contradict each other.

  • Plain search found the right article for 15 of the 20 answerable questions.
  • With the rewrite step, it found the right article for all 20.
  • With the answer rules in place, it correctly refused all 5 questions that had no answer.
  • A typical answer takes about six seconds.

This is a small, controlled test. It shows the approach works, not that it is ready for a real archive of thousands of articles with messy text, near-duplicate stories and conflicting reports. That is exactly what comes next.

6. What v1 Does Not Do Yet

  • It only checks claims against the newsroom's own archive. It cannot check government data, court records or other outlets' reporting.
  • It has been tested on short synthetic articles, not on long real ones or at scale.
  • It runs locally today. Online deployment with sign-in and producer-only permissions is still to come.
  • Answers take about six seconds, which needs to come down for live use.

What's Next

  • Dates written the way anchors say them ("20 January 2025")
  • A clear-screen control for the anchor display
  • Online deployment with sign-in
  • Testing on long articles and a much larger archive
  • Faster answers
  • Later: video moments, so a citation can point to the exact minute in a show
